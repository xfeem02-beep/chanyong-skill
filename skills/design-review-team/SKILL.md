# design-review-team

这是设计家族的第三套打法。它只审查当前对象并给修复优先级，不在审查时另起一套视觉方向。

## 按问题选一条主线

- 视觉层级、易用性、布局与一致性：用 `design-critique` 方法；需要强反方时补 `devils-advocate`。
- 按钮、错误、空状态、确认框和引导文字：用 `ux-copy` 方法。
- Token、组件、状态、命名和硬编码不统一：用 `design-system` 方法。
- 对比度、键盘、焦点、触控目标、语义和读屏：用 `accessibility-review` 方法；没有真实辅助技术测试就标为静态检查。
- 设计已定稿、准备开发：用 `design-handoff` 方法，覆盖布局、Token、组件状态、响应式、边界、动效和可访问性。

## 输出与停止规则

1. 固定对象、阶段、用户目标和现有设计系统，不偷换范围。
2. 每项发现给具体位置、影响等级、原因和最小修法；先处理阻断任务和高影响问题。
3. 有真实页面时查看渲染和交互；只有截图时不声称验证键盘、读屏或动态状态。
4. 剩余项只是已知取舍、重复意见或低影响润色时停止。
5. 审查不授权自动修复、发布或生产写入；已有同项修复授权才修改。

方法参考已核查的 Anthropic Design Plugin 1.2.0。插件能力存在时可直接调用；其他 Agent 缺少插件时使用本技能的同等检查框架，不复制其连接器和斜杠命令。
