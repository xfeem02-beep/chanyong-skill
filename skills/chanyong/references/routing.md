# 场景路由

只读命中场景。总控拥有路线和状态；专业技能只完成自己的窄任务，不能递归开启另一套总控。

## 研究与决策

先定义要回答的问题、当前日期与范围，再选多源研究或单一事实核对。推荐、趋势、价格、规则、软件与“最新”内容实时核查；技术问题优先官方文档和原始仓库。区分事实、来源推断和建议。复杂研究可生成独立报告；普通比较直接回答。

## 商业、产品与策划

明确目标用户、场景、痛点、目标、范围、不做什么、成功标准和风险。研究只补真实缺口；已有业务决定不重新访谈。需要实现时把需求写成可观察验收条件。跨系统、权限、数据合同、并发、迁移或关键取舍才启用架构；简单内容和局部页面不需要架构师。

## 架构与实现

沿用现有栈和模块边界。先检查调用方、配置、数据、测试和导出；用最小改动完成全部受影响点。新系统或重大取舍写短 ADR：背景、选项、决定、权衡、后果、后续。故障先复现和定位，不借修复重构无关代码。验证必须与最终结论匹配。

## 界面、视觉与内容

先读 [design-family.md](design-family.md)，再读现有页面、状态、设计规范和真实内容。网页、后台或应用界面默认调用内置 [Taste Skill v2](../vendor/design-taste-frontend/SKILL.md) 形成或提纯主审美方向，并在真实浏览器多尺寸检查；项目体系和用户锁定方向优先。Refero、本机参考库与 UI/UX Pro Max 只补参考和细节，不另起冲突方向。保留业务逻辑、人工确认、真实数据和可访问性。只有用户要成图或视觉选择确有价值时才制作效果稿。

用户要海报、封面、效果图、品牌视觉、产品场景图、图像提示词或跨画面统一风格时，自动读取 [prompt-visual-system.md](prompt-visual-system.md)。先锁定视觉体系，再写提示词；有生成工具且用户要成图时实际生成并看图复核。纯界面代码优化仍以项目设计系统为主，不强加图像生成流程。

## 数据、报告与 Dashboard

先定义来源、时间、单位、币种、粒度、去重键、可空性和公式。缺失不是 0，样本不是全量。订单、商品件数、包裹数等实体不能混用。报告只保留支持决策的图表；用户明确“Dashboard 整套/七阶段”才进入旧总控。

用户明确要求 Dashboard 整套时，依次完成：数据来源与口径 → 用户决策与优先级 → 信息/数据架构 → 界面实现 → 视觉细化 → 可访问性与技术审查 → 真实截图和功能验收。已有有效成果直接复用；缺少关键输入只阻塞依赖阶段。每阶段记录实际输入、产物、验证和限制，不用空文件冒充证据。

## AI、识别、提示词与评测

先定义输入、输出、拒绝、未知、冲突和人工兜底。提示词与评测成对：正常例、失败例、边界例和不可判定例。目标模型和提示词来源必须明确。没有真实模型调用就标“未实测”。条码解码、精确码查询、金额计算优先确定性方法；商品身份需完整码或候选证据，不能凭相似描述猜。

## 审查、交付与发布

审查输出按影响排序，给文件/位置/证据；只看到截图就限定为可见问题。交付写清目标、输入、约束、产物、验收和未解决项。发布前核对目标版本、必要检查、权限、回滚和真实入口；用户已明确同项发布授权时不重复确认。
