# 设计家族：从需求到真实画面

这是一套自动编排规则，不是让所有设计 Skill 同时工作。`chanyong` 先在三套打法中只选一套主组合，再调用其中真正需要的能力。用户或项目已有明确方向时只提纯和复核，不擅自改方向。宿主缺少某个外部 Skill 或工具时，使用组合 Skill 的内置方法继续，并如实说明能力差异。

## 三套打法

| 主组合 | 适用场景 | 默认组合 | 完成证据 |
|---|---|---|---|
| [`interface-design-team`](../../interface-design-team/SKILL.md) 界面设计组合 | 网站、后台、App、小程序、Dashboard、新页面与改版 | 项目规范 → Taste 主方向 → 必要参考/UI 规则/UX 文案/设计系统 → 页面实现 → 多尺寸复核 | 真实页面或方案；响应式、状态、文案和可访问性已检查 |
| [`visual-design-team`](../../visual-design-team/SKILL.md) 视觉出图组合 | 海报、封面、品牌视觉、宣传图、产品场景图、系列素材 | 视觉卡 → 必要主题 → 提示词体系 → ImageGen 素材 + Canvas 精确排版 → 成图复核 | 真实图片或明确标注未生成；产品、文字、品牌和裁切已检查 |
| [`design-review-team`](../../design-review-team/SKILL.md) 审查交付组合 | 设计挑刺、UX 文案、设计系统、无障碍、定稿验收、开发交接 | 按问题只选 critique/copy/system/accessibility/handoff 一条主线 → 分级修法 → 必要复核 | 具体位置、影响等级、最小修法与未验证项清楚 |

三套组合不能同时争夺主导。混合任务按产物顺序切换，例如“先设计页面再交接开发”先完成 `interface-design-team`，定稿后才进入 `design-review-team`；“给页面做产品主视觉”由界面组合锁定容器和尺寸，再让视觉组合只制作所需素材。

## 能力地图

| 能力/Skill | 负责什么 | 什么时候使用 | 不负责什么 |
|---|---|---|---|
| `chanyong` | 在三套打法中选主组合、说明实际使用能力、控制暂停/跳过 | 所有非简单设计任务 | 不替代设计判断或生成工具 |
| `interface-design-team` | 编排界面方向、规则、文案、系统、实现与复核 | 网页、后台、App、小程序和 Dashboard | 不负责纯海报或摄影素材 |
| `visual-design-team` | 编排视觉卡、主题、提示词、图像生成和精确排版 | 海报、封面、品牌与产品场景图 | 不负责完整应用交互流程 |
| `design-review-team` | 编排设计挑刺、文案、系统、无障碍和开发交接 | 审查、定稿、验收和交付开发 | 不在审查时擅自重做主方向 |
| 设计师 `shejishi` / `design-reference` | 读取项目规范、现有页面和组件；选择 1–2 个相关参考 | 页面设计、改版、视觉 HTML、界面审查 | 不全量套品牌，不自动改代码 |
| 内置 `Taste Skill v2` | 从产品独有内容提炼概念；生成候选方向；确定字体、配色、首屏和段落构图；用真实浏览器三种宽度检查 | 网页、落地页、后台、Dashboard、应用界面及其改版 | 不覆盖用户、品牌或项目已锁定的方向；不用于纯海报摄影 |
| `refero-design` | 用真实 styles/screens/flows 补充研究证据和可借鉴细节 | 新页面、重要改版、落地页、产品流程 | 不与 Taste 并列争夺主方向 |
| `ui-ux-pro-max` | 查询样式、配色、字体、布局、交互、可访问性和技术栈细节 | 缺设计系统、需要具体规则或实现约束 | 不覆盖项目现有设计系统 |
| 提示词视觉体系 | 把锁定的视觉方向编译成稳定、可评测的图像提示词 | 海报、封面、品牌视觉、产品场景、系列图 | 不把堆砌质量词当设计 |
| `imagegen` | 生成或编辑照片、插画、纹理、产品图和位图效果稿 | 画面主体依赖图像生成或编辑 | 不代替精确排版、SVG 或页面代码 |
| `canvas-design` | 做精确文字、版式、海报和可导出的静态成品 | 中文文字必须准确、版面关系主导结果 | 不伪造照片级产品素材 |
| `frontend-design` / 项目组件 | 把方向实现成响应式、可访问的真实界面 | 用户要页面、组件或网站代码 | 不用代码假装复杂摄影或插画 |
| `design-critique` / `ux-copy` / `design-system` | 分别检查设计、界面文字和系统一致性 | 审查组合命中对应问题时 | 不同时全开，不替代真实页面证据 |
| `accessibility-review` / `design-handoff` | 分别处理无障碍核查和开发交接说明 | 定稿验收或准备开发时 | 截图不能证明键盘、读屏或动态状态 |
| 视觉复核 | 看真实成图、截图或渲染，检查偏差并最小修正 | 每次实际出图或页面实现后 | 不用提示词或静态代码冒充验收 |

Taste Skill v2 已按 MIT 许可证内置在 [`design-taste-frontend`](../../design-taste-frontend/SKILL.md)，固定来源提交记录在其 `_upstream/source.json`。其他外部 Skill 名只是可用时的专业补充；客户不必另外安装全部第三方仓库。

## 自动选择

| 用户自然语言 | 自动路线 |
|---|---|
| “做个新页面/优化后台” | `interface-design-team`：读项目与现有界面 → Taste 主方向 → 必要补充 → 实现 → 浏览器复核 |
| “给我几个网页视觉方向” | `interface-design-team`：读品牌与独有内容 → Taste 最多 3 个候选 → 按项目真实性选最适合方向 |
| “做海报/封面/宣传图” | `visual-design-team`：视觉卡 → 主方向 → `imagegen` 素材 + `canvas-design` 精确排版 → 成图复核 |
| “生成产品场景图” | `visual-design-team`：核对真实产品 → 提示词视觉体系 → `imagegen` → 产品一致性复核 |
| “统一这一批图片风格” | `visual-design-team`：系列视觉卡 → 固定构图/色彩/光线/镜头 → 逐张生成与横向复核 |
| “只帮我写提示词” | 视觉卡 → 一份主提示词 → 必要时两个单变量变体；不生成图片 |
| “照这个截图改页面” | `interface-design-team`：截图作方向证据 → 读真实项目 → 实现可访问界面 → 截图对齐复核 |
| “做 Logo/图标” | 先查现有品牌与矢量体系；优先矢量/代码原生方法，只有概念探索才用位图生成 |
| “帮我看看页面哪里不好” | `design-review-team`：设计 critique 主线 → 具体位置与等级 → 最小修法 |
| “检查按钮文案/错误提示” | `design-review-team`：UX copy 主线 → 推荐文案、适用语气与本地化注意 |
| “检查设计系统统一不统一” | `design-review-team`：design system 主线 → Token/组件/状态/命名问题与修法 |
| “检查无障碍/交付开发” | `design-review-team`：accessibility 或 handoff 主线；只有真实测试证据才写通过 |

## 让设计师更会出画面

1. **先看真实内容**：产品、文字、受众、渠道、尺寸、已有品牌和必须保留项。缺失事实留空，不靠“高级感”补造。
2. **先锁一个方向**：网页和应用界面由 Taste 从项目独有内容提炼方向；用一句视觉主张和 3–5 个不可丢失特征锁定。最多从次要参考借 1–2 个具体细节，不取平均风格。
3. **决定画面由什么做**：照片/插画/纹理由 `imagegen`；准确中文、价格、日期、按钮、表格和排版由 Canvas 或代码；两者可组合，但职责分开。
4. **先产关键画面**：先做最能代表方向的一张，不一开始批量。关键画面通过后，再用一致性锚点扩展系列。
5. **文字单独管理**：需要逐字准确的标题、金额、型号和 CTA 不交给图像模型碰运气；生成背景/主体后再排版。
6. **每轮只改一个主因**：构图、色彩、光线、字体或素材只选一个主变量修改，避免无法判断哪项有效。
7. **必须看结果**：提示词写得漂亮不等于画面好。页面由 Taste 在真实浏览器检查多种宽度；图片检查视觉层级、产品准确性、文字、品牌、裁切、对比度、生成瑕疵和目标尺寸。

## 默认交付

设计任务按实际需要交付以下内容，不强制全部展示：

```text
正在使用：chanyong 的设计与出画面能力
目标与已有约束：一句话
主视觉方向：一句话 + 必须保留特征
出画面方式：ImageGen / Canvas / 页面代码 / 组合
结果：真实图片、可打开页面或可复制提示词
复核：看过什么、修了什么、仍未验证什么
```

用户只要结果时，内部保留视觉卡和选择依据，外部只展示必要说明与成品。用户要方案时再展开参考、视觉卡和取舍。
