# 设计家族：从需求到真实画面

这是一套自动编排规则，不是让所有设计 Skill 同时工作。`chanyong` 先识别场景；网页、后台和应用界面默认由内置 Taste Skill v2 主持审美方向，再调用必要的研究、出图、实现和验收能力。用户或项目已有明确方向时，Taste 只负责提纯和复核，不擅自改方向。宿主缺少某个外部 Skill 或工具时，使用本文件内置方法继续，并如实说明能力差异。

## 能力地图

| 能力/Skill | 负责什么 | 什么时候使用 | 不负责什么 |
|---|---|---|---|
| `chanyong` | 理解目标、自动分流、说明正在使用的能力、控制暂停/跳过 | 所有非简单设计任务 | 不替代设计判断或生成工具 |
| 设计师 `shejishi` / `design-reference` | 读取项目规范、现有页面和组件；选择 1–2 个相关参考 | 页面设计、改版、视觉 HTML、界面审查 | 不全量套品牌，不自动改代码 |
| 内置 `Taste Skill v2` | 从产品独有内容提炼概念；生成候选方向；确定字体、配色、首屏和段落构图；用真实浏览器三种宽度检查 | 网页、落地页、后台、Dashboard、应用界面及其改版 | 不覆盖用户、品牌或项目已锁定的方向；不用于纯海报摄影 |
| `refero-design` | 用真实 styles/screens/flows 补充研究证据和可借鉴细节 | 新页面、重要改版、落地页、产品流程 | 不与 Taste 并列争夺主方向 |
| `ui-ux-pro-max` | 查询样式、配色、字体、布局、交互、可访问性和技术栈细节 | 缺设计系统、需要具体规则或实现约束 | 不覆盖项目现有设计系统 |
| 提示词视觉体系 | 把锁定的视觉方向编译成稳定、可评测的图像提示词 | 海报、封面、品牌视觉、产品场景、系列图 | 不把堆砌质量词当设计 |
| `imagegen` | 生成或编辑照片、插画、纹理、产品图和位图效果稿 | 画面主体依赖图像生成或编辑 | 不代替精确排版、SVG 或页面代码 |
| `canvas-design` | 做精确文字、版式、海报和可导出的静态成品 | 中文文字必须准确、版面关系主导结果 | 不伪造照片级产品素材 |
| `frontend-design` / 项目组件 | 把方向实现成响应式、可访问的真实界面 | 用户要页面、组件或网站代码 | 不用代码假装复杂摄影或插画 |
| 视觉复核 | 看真实成图、截图或渲染，检查偏差并最小修正 | 每次实际出图或页面实现后 | 不用提示词或静态代码冒充验收 |

Taste Skill v2 已按 MIT 许可证内置在 [`vendor/design-taste-frontend`](../vendor/design-taste-frontend/SKILL.md)，固定来源提交记录在其 `_upstream/source.json`。其他外部 Skill 名只是可用时的专业补充；客户不必另外安装全部第三方仓库。

## 自动选择

| 用户自然语言 | 自动路线 |
|---|---|
| “做个新页面/优化后台” | 读项目与现有界面 → Taste 形成或提纯主方向 → 参考与 UI 规则补充 → 实现 → Taste 浏览器复核 |
| “给我几个网页视觉方向” | 读品牌与独有内容 → Taste 生成最多 3 个候选 → 按项目真实性选最适合方向 → 用户选择或按授权选最优 |
| “做海报/封面/宣传图” | 视觉卡 → 主方向 → 图像素材用 `imagegen`，准确文字与版式用 `canvas-design` → 成图复核 |
| “生成产品场景图” | 核对真实产品与必须保留项 → 提示词视觉体系 → `imagegen` → 产品一致性复核 |
| “统一这一批图片风格” | 找共同锚点 → 建系列视觉卡 → 固定构图/色彩/光线/镜头 → 逐张生成与横向复核 |
| “只帮我写提示词” | 视觉卡 → 一份主提示词 → 必要时两个单变量变体；不生成图片 |
| “照这个截图改页面” | 把截图作为方向证据 → 读真实项目 → 实现可访问界面 → 截图对齐复核 |
| “做 Logo/图标” | 先查现有品牌与矢量体系；优先矢量/代码原生方法，只有概念探索才用位图生成 |

## 让设计师更会出画面

1. **先看真实内容**：产品、文字、受众、渠道、尺寸、已有品牌和必须保留项。缺失事实留空，不靠“高级感”补造。
2. **先锁一个方向**：网页和应用界面由 Taste 从项目独有内容提炼方向；用一句视觉主张和 3–5 个不可丢失特征锁定。最多从次要参考借 1–2 个具体细节，不取平均风格。
3. **决定画面由什么做**：照片/插画/纹理由 `imagegen`；准确中文、价格、日期、按钮、表格和排版由 Canvas 或代码；两者可组合，但职责分开。
4. **先产关键画面**：先做最能代表方向的一张，不一开始批量。关键画面通过后，再用一致性锚点扩展系列。
5. **文字单独管理**：需要逐字准确的标题、金额、型号和 CTA 不交给图像模型碰运气；生成背景/主体后再排版。
6. **每轮只改一个主因**：构图、色彩、光线、字体或素材只选一个主变量修改，避免无法判断哪项有效。
7. **必须看结果**：提示词写得漂亮不等于画面好。页面由 Taste 在真实浏览器检查多种宽度；图片检查视觉层级、产品准确性、文字、品牌、裁切、对比度、生成瑕疵和目标尺寸。

## 默认交付

设计任务按实际需要交付以下内容，不强制全部展示：

```text
正在使用：chanyong 的设计与出画面能力
目标与已有约束：一句话
主视觉方向：一句话 + 必须保留特征
出画面方式：ImageGen / Canvas / 页面代码 / 组合
结果：真实图片、可打开页面或可复制提示词
复核：看过什么、修了什么、仍未验证什么
```

用户只要结果时，内部保留视觉卡和选择依据，外部只展示必要说明与成品。用户要方案时再展开参考、视觉卡和取舍。
