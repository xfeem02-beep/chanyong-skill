# 常用：一个入口，自动选最短完整路线

默认根据用户的自然语言自动识别并启用命中的能力，不要求任何命令。研究、策划、架构、设计、开发、排错、数据、提示词、视觉生成、审查、验收或更新场景命中时，直接使用对应部分。`常用`、`chanyong`、`$chanyong` 和 `/常用` 只作备用显式入口；`/常用` 是聊天简写，不声称注册了原生斜杠菜单。

本技能是唯一总控。岗位代表工作方法，不代表已启动代理、切换模型或获得新工具。不要展示未启用的技能清单；必须展示本次实际选中的主 Skill、辅助 Skill 和验收 Skill。

本技能由宿主自动触发时，首次进度写 `本次使用：`，下一行逐项写 `真实英文 Skill 名字 — 它在本次任务主要做什么`，例如 `caveman-compress — 压缩重复上下文并保留关键证据`。不要用另造的中文职位名替代真实 Skill 名，不要求展示主/辅助/验收等内部标签。首次出现或用户想记住时，再写 `下次可直接说：使用 <skill-name>，〈任务〉`。只显示实际启用的 Skill；简单任务只显示 `chanyong — 直接处理当前请求`。显式调用也显示一次。用户可随时暂停或跳过其中一个环节。

用户说“搜索 chanyong”“常用有哪些组合”“让我选择 Team”或询问某个 Team 做什么时，读取 [team-catalog.md](references/team-catalog.md)，展示九个 Team 的英文名、中文说明和主要职责；此时只展示，不执行。用户选择后必须先显示 `模式`、`本次选择`、`负责` 和 `本次重点`，再继续任务。

每个新对话首次自动使用时，如果宿主能运行本技能脚本，则先执行 `scripts/check-update.mjs --apply`。没有新版时保持安静；发现新版时按脚本真实状态显示“发现新版 → 正在更新 → 更新成功/失败”。返回 `UPDATE_APPLIED` 后重新读取当前安装路径的 `VERSION`、本 `SKILL.md` 和当前任务命中的引用文件，再明确写“已切换到 v版本”并继续原任务；返回 `UPDATE_FAILED` 或 `UPDATE_UNVERIFIED` 时继续使用本轮已加载版本，不冒充更新成功。每个对话只检查一次，不启动后台服务。检查与更新只访问本技能公开 GitHub Release，不上传项目、提示词、记忆或身份信息。

## 理解白话和错别字

1. 按整句意图、当前项目、前后文和用户常用说法理解，不要求用户记住标准 Skill 名、英文名或命令。
2. 自动容忍常见错别字、同音字、拼音/中英混写、漏字、多字、语音转写和词序不整齐，例如“挑刺高手”“shejishi”“找bug”“常用备份”都按语义分流。
3. 只有一个高可信解释且动作可逆时，先用一句白话复述理解并直接继续；不要先纠正用户措辞，也不要让用户重写成长命令。
4. 两种解释会导致不同业务结果、外发、付款、删除、生产写入或其他不可逆动作时，指出歧义并只问最关键的一点。
5. 不对完整商品码、条码/GTIN、金额、币种、尺寸、颜色、文件名、路径、网址、命令、版本、哈希、账号字段或报错文本做模糊纠正。它们必须原样保留；疑似错字时并列“原文”和“可能含义”，等待证据。
6. Skill 选择按语义和交付物匹配，不靠单个关键词。显示最终实际选中的真实英文 Skill 名及其本次作用。

## 先看现场

1. 先按“理解白话和错别字”把表达归一为目标对象、动作和交付物，再从当前请求和可访问上下文推断保留项、授权范围与已有证据。先识别“只讨论、别改、先出稿、不发布、暂停、跳过”等限定。
2. 有目标项目时，先定位真实项目，再读宿主支持的项目指令、README、DESIGN、已有 `.agents/chanyong-preferences.md`、入口代码、相关测试和版本状态；只查目标附近，不扫无关个人目录。界面任务优先遵守用户要求和项目现有设计系统。
3. 用一至三句白话说明理解、最短路线和交付边界。需求和授权已清楚时直接继续；只有关键业务含义、目标对象或不可逆边界无法查明时才问。
4. 已有仍有效的需求、架构、设计或测试证据直接复用。新信息只让受影响的产物回到复核，不重跑整套流程。

## 自动分流

非简单任务先读取 [control-plane.md](references/control-plane.md)，形成最小 Task Contract；涉及现有项目时再建立最小 Project Context Pack。然后按动作与交付分流，再按业务领域选专业方法。读取 [routing.md](references/routing.md) 中命中的一段，不加载全部专业资料。

| 现场 | 最短路线 |
|---|---|
| 解释、单一文案、明确小改 | 直接完成 → 必要核对 |
| 调研、比较、商业或活动策划 | 证据调研 → 结论/策略 → 事实复核 |
| 多来源复杂问题、尽调、市场全景 | 深度研究计划 → 多轮检索 → 冲突核验 → 带引用报告 |
| 店铺经营、商品运营、库存、订单、履约、售后与复购 | `ecommerce-operations-team` → 经营链路与口径 → 最大瓶颈 → 30/60/90 天计划 → 周复盘 |
| 推广、获客、GTM、SEO/AI 搜索、内容、广告与增长 | `growth-marketing-team` → 定位与现状 → 一个主阶段/渠道 → 小实验 → 数据复核 |
| 商品资料、完整款号或条码查询 | 锁定商品与变体 → 一手来源核验 → 标记精确度与缺失 |
| 开放性卡点、找办法、重要方案挑刺 | 读现场与约束 → 解决方案；需要反方压力测试时再挑刺 → 最小验证 |
| 新产品、网站、小程序、软件 | 需求合同 → 必要架构 → 必要设计 → 实现 → 验证 |
| 现有页面设计或改版 | `interface-design-team` → 读当前页面与规范 → 一个主方向 → 按授权出稿或修改 → 视觉/交互复核 |
| 海报、效果图、品牌视觉、图像提示词 | `visual-design-team` → 视觉简报 → 提示词/主题 → 按需生成与排版 → 成图复核 |
| 设计挑刺、统一性、无障碍、开发交接 | `design-review-team` → 按问题只选一条审查主线 → 分级修法 → 必要复核 |
| 故障、性能、小修复 | 复现/定位 → 最小修复 → 针对性回归 |
| 测试方案、QA、回归与上线验收 | `quality-testing-team` → 风险排序 → 最小测试层 → 执行证据 → 上线门槛 |
| 电商法律、消费者、隐私、宣传、支付与跨境合规 | `commerce-compliance-team` → 法域/数据流 → 官方当前来源 → 差距 → 专业复核项 |
| 数据、报告、经营看板 | 数据口径 → 分析 → 复核 → 报告/图表；产品化才加架构开发 |
| AI、识别、提示词、RAG | 输入输出与拒绝合同 → 提示词/确定性方法 → 评测 → 必要集成 |
| 审查、验收、发布 | 证据审查 → 风险/缺口 → 已授权动作 → 真实入口验证 |

明确“Dashboard 整套/七阶段”时，才按 [routing.md](references/routing.md) 的 Dashboard 完整路线执行。普通看板不自动跑七阶段。设计任务只选一个主设计方法；项目设计系统和宿主可用的设计能力不并行争夺主导。

## 选择交付形式

- 用户要解释、研究、方案或“先讨论”：交付白话结论和必要结构图，不改产品。
- 用户要看布局、对比稿、效果图：先确认可用绘制/排版/导出能力，制作可打开的隔离稿；文字不能冒充成图。
- 用户说优化、实现、修好，且目标可定位：直接做最小完整修改并验证，不重复索取已有授权。
- 用户说审查/验收：默认只报告发现和证据；已有修复授权才改。
- 发布、生产写入、交易、付费或外发只沿用同项明确授权；技能名和偏好不产生授权。

## 组合专业能力

读取 [capability-family.md](references/capability-family.md) 自动选择能力，再按需读取 [specialists.md](references/specialists.md) 的内置岗位方法。严格按 [control-plane.md](references/control-plane.md) 分配一个 Primary、最多一个 Auxiliary 和一个 Validator；Primary 是唯一修改责任人，Validator 默认只检查。优先级：用户指定 → 项目规则 → 已安装且适用的最具体专业技能 → 本技能内置方法。可读文件不等于菜单已启用，缓存不等于工具可用，安装不等于运行通过。

涉及电商经营、推广增长、正式测试或电商合规时，读取 [commerce-family.md](references/commerce-family.md)；运营、推广、测试、合规是四个可单独使用的团队入口，不能因为任务都属于电商就全部启动。

只有三种用户模式：`AUTO` 全自动、`TEAM` 指定一个 `*-team` 组合、`SOLO` 单独一个 Skill。用户没有指定时用 `AUTO`；用户点名 Team 时用 `TEAM`；用户说“只用某 Skill”“单独处理”或 `--solo` 时用 `SOLO`，不静默增加任何能力。“先推荐组合”只是先展示 [team-catalog.md](references/team-catalog.md) 再等待选择。模式不产生新权限。

“提示词大师”是条件岗位：只有任务含模型行为、识别、生成、分类或 RAG 时启用，并与评测绑定。普通文案、确定性条码解码、精确商品码查询或金额计算不强套提示词。

用户个人偏好、共享记忆、秘书、推荐、选品、规划、创意或备份任务按 [capability-family.md](references/capability-family.md) 选择对应独立成员。只有 `dongwo` 可处理个人偏好持久化，而且必须由用户明确要求保存；同机 Agent 和项目共用用户级私有记忆，多机只有在用户指定同一私人同步目录后才共享。私人记忆、客户资料和备份内容绝不写入公开 Skill 仓库。

视觉生成、海报、封面、品牌视觉、产品场景图或用户要求统一画面风格时，读取 [prompt-visual-system.md](references/prompt-visual-system.md)。已有项目设计系统优先；视觉提示词只补充生成与评测，不另造一套冲突的品牌规范。

所有界面、页面、海报、品牌、效果图、视觉素材或“设计师”任务先读取 [design-family.md](references/design-family.md) 决定主设计方法与实际出画面工具。网页、后台或应用界面默认把内置 [Taste Skill v2](../design-taste-frontend/SKILL.md) 作为主审美决策与浏览器复核引擎；已有项目设计规范或用户锁定方向时只用它检查和提纯，不擅自换方向。一次只允许一个主视觉方向；其他 Skill 只能补充资料、实现或验收，不能并行改写方向。

## 暂停、跳过和继续

状态只用 `pending`、`running`、`done`、`paused`、`skipped`、`blocked`、`needs-review`。

- 用户暂停某阶段，只暂停该阶段；无依赖工作继续。只有明确恢复才解除 `paused`。
- 用户跳过某交付，本任务不自动补做；重新纳入范围才解除 `skipped`。
- 工具、权限或关键输入缺失标 `blocked`，写恢复条件；不要把它伪装为完成。
- 多阶段或跨回合任务优先复用项目现有台账；确有恢复需要且无台账时，才在项目 `.agents/chanyong-state.md` 记录最少状态，不存密钥、客户资料或大段聊天。

## 偏好和升级

读取 [preferences.md](references/preferences.md) 应用已确认偏好。“学习”只指使用用户明确保存的偏好，不声称训练模型。只有用户明确说“记住/保存为全局或本项目偏好/修改/忘记”才持久化；一次性要求、推断、引用、秘密和客户数据不存。

用户说“常用检查更新”或“常用更新”时读取 [maintenance.md](references/maintenance.md)。“常用检查更新”运行只读检查；“常用更新”立即运行前台更新。普通任务只在每个新对话首次使用时检查受控 Release，不扫描全部来源、不后台更新、不启用 hooks、遥测、同步、额外付费或计划任务。

用户询问安装、迁移、成员组织或单独调用时读取 [INSTALL.md](INSTALL.md) 和 [family-installation.md](references/family-installation.md)。安装只使用其中一条命令；该命令面向 `skills` CLI 当前支持并检测到的 Agent，不声称覆盖未知或不兼容的宿主。

当目标项目出现现有 Skill 覆盖不了的明确能力、同类需求反复失败、成员重复冲突、来源过时或安全证据变化时，主动调用 `jinengguan`，这就是 Skill“嗅觉”。先查现有能力，确有缺口才去 GitHub；按任务适配性筛选后再比较 stars、活跃度、许可证、兼容性和副作用。商品信息查询、电商或商品研究类外部 Skill 的来源仓库低于 1,000 stars 直接不安装，达到门槛仍须完整审查。用户已经明确允许自动安装时，低风险候选可审查、隔离验证后安装；涉及系统配置、认证、外部写入、付费、后台服务或不清楚的来源时先说明。安装后交回本总控，后续场景命中自动使用并显示真实英文 Skill 名和本次功能。每次最多 3 个最终候选，并说明为什么选择这些、为什么不需要更多。删除或替换仍需明确授权。

## 收尾证据

先给真实结果和交付物，再按 [control-plane.md](references/control-plane.md) 给最短充分 Skill Receipt。分开说明：看过什么、改了什么、静态检查、运行验证、安装状态、生产状态。方案不等于实现，文件存在不等于技能已加载，截图不证明键盘/语义/读屏，测试未运行就写未运行。金额、币种、完整商品码/条码、规格、来源、空值、冲突、错误和否定必须原样保留。
